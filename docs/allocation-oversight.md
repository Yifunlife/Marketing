# 运营分配监督

入口：客户资料 → 分配与业绩；API `/api/allocation`。仅主管理员可读取。业务CRM沿用现有分配配置、首次正式分配与未取消成交记录，运营不执行客户分配、不写CRM。

月份按上海时区界定；观察期按分配后完整天数计算。仅 cohort=new 的首次正式分配进入统计，排除历史导入及模拟。成交须属于同一客户、业务范围及原分配业务员，且不早于分配、不晚于考核月末。同一客户多笔成交只计一次。它代表CRM成交登记，不代表已收款；暂不能按“有效客户”计算（尚无统一有效性审核字段）。

次月建议 = 平均权重 × 平均份额 + 业绩权重 × 成熟客户成交率占比。无成熟样本使用团队平均成交率，全员无成交回到平均，暂停或停用人员为零。份额以最大余数法保留两位小数，总计100%。首月设置业绩权重为0。业务CRM原有保底、调整上限和承接限制不在此试算中应用，明确提示在CRM执行前复核。

保存建议时服务端重新读取CRM并计算，追加不可覆盖的运营快照到 allocation_reviews，保存操作人和时间。该留档不具有业务CRM确认状态；页面独立显示CRM正式月度方案状态。当前无自动发布、自动调整或写客户归属功能。每次读数标明截止与读取时间，读取失败保留旧结果并禁用留档。

业务CRM已有规则配置入口，规则管理和实际执行继续在那里维护。各平台询盘接入、联系方式跨线索查重及新旧/有效性核验尚未全部自动化，现有运营线索交接流程保持人工核实、CRM查重及关联。
